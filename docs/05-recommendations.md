# 05 — คำแนะนำเพิ่มเติม (จาก 5 บทบาท)

## Manager WH
1. **Staging lane ต่อตู้** — กำหนดพื้นที่หน้า dock เป็นช่อง "ตู้ A / ตู้ B" ของที่หยิบแล้ววางรอตามลำดับโหลด ลดการค้นหาหน้างาน
2. **Cut-off time** — กำหนดเวลาล็อกแผน (เช่น D-1 16:00) หลังจากนั้นแก้ได้เฉพาะผู้มีสิทธิ์ + บันทึกเหตุผล
3. **Roll-over** — ของที่ลงตู้ไม่หมดย้ายไปแผน/ตู้ถัดไปได้ในคลิกเดียว ไม่ต้องสร้างใหม่
4. **Cycle count รายวันเฉพาะตำแหน่งที่มีปัญหา** แทนการนับทั้งคลัง

## Staff WH
1. **LPN ทุกพาเลท** — สแกนครั้งเดียวรู้ทุกอย่าง ไม่ต้องพิมพ์ SKU/จำนวน
2. **ป้ายตำแหน่ง QR ทุกช่อง + ตัวอักษรใหญ่** อ่านได้จากรถโฟล์คลิฟท์
3. **รูปถ่ายเป็นหลักฐาน** — ตู้เปล่า / ครึ่งตู้ / เต็มตู้ / seal ป้องกันข้อโต้แย้งเรื่องของเสียหายหรือขาด
4. หน้าจอบอกแค่ "งานต่อไป" ไม่ต้องเลือกจากรายการยาว

## Director
1. **KPI หลัก 5 ตัว**: % เต็มตู้เฉลี่ย, ตู้ส่งตรงเวลา, ความแม่นยำการหยิบ, Dock-to-stock (ชม.), ค่าใช้จ่ายต่อตู้
2. **% เต็มตู้ = เงิน** — ตู้ 40HC ที่เต็ม 85% → 95% ลดจำนวนตู้ต่อปีได้ชัดเจน ใช้ตัวนี้วัดความคุ้มค่าของระบบ
3. เริ่ม pilot แคบ (1 ลูกค้า 1 สาขา) แล้วค่อยขยาย

## Senior Dev
1. **Stock ledger แบบ append-only + idempotent scan** — ป้องกันยอดเพี้ยนเมื่อ handheld ส่งซ้ำตอนเน็ตหลุด
2. **ผังคลังเป็นข้อมูล (มีพิกัด/ขนาด)** ไม่ใช่รูปวาด → 2D, 3D, putaway, route ใช้ข้อมูลชุดเดียว
3. **Vendor adapter แยกต่อเจ้า** เริ่มด้วย import/export ไฟล์ อย่าเริ่มที่ RPA
4. 3D ใช้ instanced mesh + LOD, โหลดเฉพาะ zone ที่ดู
5. ทำ container-fit เป็น package แยก มี test case จากตู้ที่โหลดจริง (golden data)

## Senior UX/UI
1. Handheld: 2D + ข้อความใหญ่, 3D เก็บไว้สำหรับแท็บเล็ต/จอใหญ่ที่ dock
2. **จอทีวีที่ dock** แสดง Loading Monitor — ทีมเห็น progress พร้อมกัน
3. สีสถานะชุดเดียวทั้ง web/mobile/2D/3D/label
4. ทดสอบกับ staff จริง 3 คนก่อน freeze หน้าจอ M4/M5/M6 (paper prototype ก็พอ)

## ฟีเจอร์ที่ควรพิจารณาเพิ่ม
- แจ้งเตือน LINE OA/Group: รถสาขาออกแล้ว, ตู้โหลดเสร็จ, ของไม่พอ
- พิมพ์ Shipping mark / carton label ตามแบบลูกค้า
- Dock scheduling — จองช่วงเวลา dock ให้รถตู้/รถสาขา ไม่ให้ชนกัน
- ประวัติการโหลดเพื่อปรับตัวคำนวณตู้ให้แม่นขึ้น
